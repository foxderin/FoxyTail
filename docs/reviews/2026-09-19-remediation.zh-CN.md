## 配置生效规则

- 普通设置保存只更新 `conf/` 并标记 pending。watchdog、context、DNS、路由、tun、stats、logd 的运行/恢复读取 `run/applied-config` 指向的快照。
- 显式冷启动或重启选择一个已校验候选，包含 main/routes/context 和 revision；停止期间的另一笔保存不会改变该候选。冷启动也会先清理可能存活的旧 HEV/DNS/路由组件。
- 已运行服务的重复 start 只按 applied 配置协调，不读取损坏的待应用配置。context 的 up 使用 `start --applied`，能撤销之前 down 留下的手动停止标记；watchdog 的 recover 仍尊重手动停止。
- routes/context 的显式热应用只提升对应文件，不顺带激活其他 main 设置。路由 API 的 IPv6 跳过结果来自运行配置。context 保存复用驻留组件重载，确认进程启动或合法空操作后才返回成功；这不代表网络场景动作已成功完成，动作失败仍由原循环重试。
- 完整 `start.sh reload` 仅在组件启动通过后清除匹配快照 revision 的 pending；更新的保存仍保留。单独热应用不会清除其他配置的待重启标记。
- 无快照且无 pending 时兼容旧安装；无快照但已有 pending，或快照指针/文件损坏时，不猜测当前运行配置，要求显式重启应用。

## 输入与兼容性说明

- 场景规则仍是简单行格式，不增加 DSL。SSID 中的冒号、`#`、双引号、控制字符与未知网络占位符会明确拒绝；空格、反斜杠、UTF-8 名称按字面匹配。见 `tailscale/conf/context.conf`。
- 修改的是仓库内 tun hook 模板；没有覆盖设备上用户自定义的 hook，也没有在设备上运行安装、卸载或网络变更。
- 旧 `.reap` 遗留对象不再参与新协议，保持原样；新锁扫描等待者为 O(n)，并非吞吐优化。旧版与新版控制器同时争用的全部时序未获认证，正常升级仍应先静止旧控制器。
- 历史 applied 快照在 context 未运行时回收；context 存活期间保留旧快照，避免删除它正在读取的规则。
