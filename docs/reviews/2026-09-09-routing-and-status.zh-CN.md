# FoxyTail v1.2.0 路由与首页状态卡

本次新增接收其他 Tailscale 节点通告的子网路由，完善自定义 IPv4／IPv6 网段编辑，并根据实际 KernelSU 首页截图调整 Tailnet 状态卡。

## 首页状态卡

采用 KernelSU「工作中」卡片的整块色面、圆角和左侧线框状态图标。保留充足留白，不缩成紧凑信息条；移除原来的顶部色条与独立图标底框。图标继续使用 Material Symbols 官方 SVG。

正常连接只显示「已接入 Tailnet」，不重新加入运行模式、重复设备名或刷新频率。连接中、未授权、已停止和读取失败分别使用对应状态；未知状态不会显示成已停止或继续使用已连接样式。首屏骨架与实际卡片布局对应。

## 路由操作

路由页顶部提供「接收节点路由」开关和刷新。开关读写当前 Tailscale 账户的 `RouteAll` 实际偏好，只调用 `tailscale set --accept-routes` 修改这一项；不复制到模块配置。写入后读取实际值核验，操作可跨页面继续，旧响应不能覆盖新结果。

节点通告按设备分组，显示 CIDR、主用信息和节点在线状态。只过滤节点自身的 Tailnet 地址及出口默认路由，保留合法的 IPv4 `/32`、IPv6 `/128` 主机路由。节点在线不等于目标网段已经可达。

「添加」将通告中的 CIDR 放入本地编辑草稿；手工输入、删除和应用范围也只修改草稿，点击「保存并应用规则」后才保存。刷新节点通告不会重载或覆盖本地未保存编辑。IPv4／IPv6 地址规范化为网络地址，并按规范结果去重，包括压缩 IPv6 与嵌入 IPv4 的 IPv6 表示。

接收偏好与本地网段有不同作用：前者允许 Tailscale 使用控制面许可的节点路由，后者选择 FoxyTail 本地策略路由的目的地址。自定义列表不是接收白名单，导入网段不会将下一跳固定到通告节点。路由审批、访问控制和对端转发仍由 Tailnet 与子网路由器配置决定。

| 模式 | 接收与本地规则的关系 |
| --- | --- |
| 原生 TUN | tailscaled 管理接收的系统路由；自定义 CIDR 还可以使用 FoxyTail 本地策略优先级。仅支持全局应用范围。 |
| 桥接 | 接收偏好决定 Tailscale 可使用的节点路由，目标 CIDR 还需加入本地列表，并遵循应用范围。 |
| SOCKS5 代理 | 接收路由用于代理连接，不安装 Android 系统路由。 |

## 状态与失败处理

- 未知接收状态使用禁用的不确定开关，操作期间保留最后确认值，核验后才更新实际状态。刷新确认恢复后会清理过期的不一致提示。
- 原生桥非零退出时保留结构化错误中的已知实际值，失败不会因为响应中的其他字段而变成成功。
- IPv6 关闭时仍可先保存手工 IPv6 网段，明确列出未应用网段并提供设置入口；返回页面仍能看见待启用状态。
- 本地路由重载失败与 IPv6 未启用分别记录。IPv6 提示不会覆盖实际应用错误，也不会把仅保存的配置显示为全部应用完成。

## Funnel 协议修复

设备返回 `flag provided but not defined: -http` 的原因是 Serve 与 Funnel 共用了协议列表和命令拼接。对照当前固定版本源码及真机 CLI 帮助，只有 Serve 注册 `--http`，Funnel 支持 `--https`、`--tcp` 与 `--tls-terminated-tcp`。

Funnel 的公网监听协议与本地目标协议分别处理：本地 `http://localhost:3000` 服务通过公网 HTTPS 监听转发。前端不再提供 Funnel HTTP 监听，切换用途时调整不兼容的监听选项并保留目标；后端独立校验协议及 Funnel 公网端口，非法组合在调用 CLI 前拒绝。私网 Serve 的 HTTP 功能保留。

## 验证与边界

完整检查通过：91 项后端测试、ShellCheck、类型检查、517 项中英词条检查、主题一致性、23 组 WebUI smoke、生产资产重建一致性和发布元数据检查。前后端 CIDR 规范化对照覆盖全部 IPv4／IPv6 前缀长度、主机路由、默认路由和嵌入 IPv4 的 IPv6；回归覆盖未知状态、非零原生退出、跨页操作、失败后刷新、草稿保留、IPv6 待启用与重载失败组合，以及 Serve／Funnel 的协议、端口、HTTP 目标保留和精确删除。

浏览器检查了首页状态卡的手机深浅主题与失败样式、路由页的手机中文和桌面英文布局；两种尺寸均无水平溢出，实际点击导入后刷新仍保留未保存网段。保存栏按当前底部导航高度避让，桌面端不再留出手机导航空间。

Android 16／KernelSU 3.3.0 真机已验证新版子网接口：模式为原生 TUN，接收偏好与 IPv6 均开启，读取约 1.2 秒；对已开启状态重复设置保持幂等，非法参数被拒绝。设备自带 awk 对 IPv4、IPv6、IPv4 嵌入 IPv6 的网络地址规范化和去重符合预期。部署前后模块配置文件校验值一致，保留了原脚本备份。

Funnel 修复也已部署真机：HTTP 公网监听、非法公网端口和作为控制命令的目标均在 CLI 调用前被拒绝，响应为简短的具体错误。前后读取的 Serve 配置完全一致，模块配置和已有映射未变化；没有为了验证而创建公网映射。最终生产 WebUI 的 3 个文件与部署文件校验一致，重新打开管理器 WebUI 后加载新界面。

当前设备没有可见的非默认子网通告，因此没有声称已完成真实子网目的地址连通性测试。包含多个通告节点、离线状态、导入与失败的场景使用隔离模拟数据验证。真实设备数据与参考截图保存在忽略的构建目录，不进入源码提交或发布包。
