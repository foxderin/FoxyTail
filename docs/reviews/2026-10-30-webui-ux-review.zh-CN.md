# FoxyTail Web UI 交互与视觉审查（2026-10-30）

审查基线：`f06ef347f1e12cc05c56f8dfb655cfe28bba3333`，v1.9.0。审查对象为 `webui/src/**` 的全部页面与共享组件。本报告只关注 UI 与交互设计；前后端契约问题见 `findings/2026-10-30-webui.zh-CN.md`。审查阶段仅增加报告，未修改运行代码。

## 方法

- 通读 `webui/src` 下的页面、组件、样式与词典。
- 运行 `pnpm dev` 打开 `dev/index.html` 模拟预览，通过 Chrome DevTools 协议做设备仿真截图。尺寸覆盖手机 412×915、360×740，平板 1024×800，桌面 1280；主题覆盖浅色与深色，语言覆盖中文与英文。
- 状态覆盖 `ready / login / stopped / error / no-root / unknown / empty / proxy`；实际操作了设置草稿、保存确认弹窗、服务停止确认、节点详情与任务菜单。
- 布局问题以 DOM 实测数值为准（如顶栏高度、反馈行子元素宽度）。截图保存在本地临时目录，不随仓库提交。
- 只由模拟数据造成的异常不计入问题（例如 proxy 模式下 tailscale0 显示为已启用）；但"界面没有按状态屏蔽旧数据"属于 UI 问题，照常记录。

## 总体判断

状态正确性做得很扎实：代际校验、写后核验、草稿恢复在多数页面已经到位。主要问题是把内部工程模型直接暴露给用户。用户需要理解"保存 / 应用 / 试用 / 确认 / 核验 / 未确认回执"六个概念，而他们真正想做的只是开关连接、选出口、看设备、传文件。问题归为六类：

| 类别 | 核心问题 |
| --- | --- |
| 一、信息架构 | 导航位置与使用频率不匹配；诊断入口分散；设置页内容堆积 |
| 二、全局外壳 | 常驻界面元素占屏过多，且放置了高风险控件 |
| 三、提交模型 | 同一应用内存在 9 种生效方式，开关语义被破坏 |
| 四、状态反馈 | 同一状态重复表述，关键状态却缺少可执行操作 |
| 五、可发现性 | 纯图标操作过密、图标语义冲突、详情页不可操作 |
| 六、视觉排版 | 字号偏小、禁用态像可用态、组件对齐不一致 |

## 一、信息架构：导航位置与使用频率不匹配

| 问题 | 位置 |
| --- | --- |
| 底栏 5 个位置之一给了低频的"流量"；Tailscale 最常用的出口节点被放在"节点"页底部，排在整个设备列表之后 | `webui/src/navigation.ts:37-43`、`webui/src/pages/Peers.tsx:293-296` |
| 诊断入口分散在 4 处：诊断页；设置 › 高级 › 诊断（两层折叠，列出 21 条原始 DNS 字段）；隧道 › MagicDNS 检查；日志 | `webui/src/pages/SettingsMaintenance.tsx:74-99` |
| 设置页内容堆积：外观、网络、后台、试用、高级（路由表、情景规则、hooks、诊断）、备份、恢复，手机上约 4000px 高。"情景规则"本身是自动化功能，却藏在"高级"里 | `webui/src/pages/Settings.tsx:257-372` |
| 默认的 TUN 模式下，路由页"流量范围"整卡都是禁用的单选 | `webui/src/pages/Routing.tsx:207-235` |
| 桌面端重复：侧栏有"更多"，点进去的页面只是把侧栏再列一遍；桌面也显示"返回工具"；品牌副标题"网络控制台"、面包屑"网络控制台 › 仪表盘"、H1"仪表盘"同时出现；首页"常用功能"与导航重复 | `webui/src/navigation.ts:40`、`webui/src/components/AppShell.tsx:165-167`、`webui/src/pages/Dashboard.tsx:323-361` |

### 方案

底栏改为 **首页 · 设备 · 文件 · 网络 · 设置**，去掉"更多"；桌面侧栏使用同样的五组。

- **首页**：连接卡（开关、状态、本机地址）、出口节点行（点开底部弹层）、在线设备摘要、今日流量摘要、问题提示。
- **网络**：合并原隧道、路由、Serve / Funnel、代理共存。"运行模式"做成带说明的单选卡片放在这里。TUN 模式下把按应用路由折叠，写明"需要桥接模式"并给出切换入口。
- **设置**：页面顶部列账户、日志、诊断、备份恢复、关于；其下按"外观 / 网络参数 / 后台 / 高级"拆成子页。情景规则提到"网络"或单独成项。
- **诊断**：只保留一个入口，内容为"一键体检结果 + DNS 明细（可展开）+ 导出诊断包"。删除设置里的重复副本；隧道 DNS 卡只显示摘要并链接到诊断。
- **流量**：首页放摘要，详情作为二级页。

## 二、全局外壳：占屏过多，且放置了高风险控件

1. **常驻界面元素占 23% 屏高**。实测顶栏 138px、底栏 75px，在 915px 屏上占 23%，在 740px 屏上占 29%。360px 宽时，文件页首屏只能看到 1 个文件。
2. **运行模式下拉框常驻在每一页顶栏**。这是低频、高风险、会重启服务的操作，却在任何页面上都只差一次误触。360px 英文界面下标签被截断为"Native TU"。位置：`webui/src/components/ServiceControls.tsx:261-280`。
3. **"□"停止按钮在正常状态下也一直显示**。显示条件为 `canStop && !busy`，而 `canStop = compatible && commands.contains("control")`，正常情况下恒为真（`android/app/src/main/java/dev/foxderin/tail/ControlClient.java:80`）。它与服务开关功能重复，又是没有文字的小方块，看起来像复选框。位置：`webui/src/components/ServiceControls.tsx:295-302`。
4. **任务菜单使用 `sync` 图标**，看起来像刷新按钮。进入设置页时，后台 `dns-probe` 会生成一条无名的"后台任务 / 已完成"，原因是任务名回退到通用文案。位置：`webui/src/components/AppShell.tsx:60-62`。
5. **反馈行 CSS 缺陷**。`.service-controls-feedback > span { flex: 1 }` 同时匹配了 MdIcon 渲染出的 `span.md-icon`。error 状态下实测图标占 157px，提示文字被挤到右半边。位置：`webui/src/style.css:64-65`。

### 方案

- 手机顶栏改为单行 56px：页面标题 + 状态胶囊。点胶囊弹出底部面板，内含服务开关与重启。
- 有任务进行时才显示带数字的任务指示；只读探测不登记为任务；每个任务都要有可读名称。
- 运行模式切换移到"网络"页。
- 停止按钮只在 `canStop && !canWrite` 时出现，并带"紧急停止"文字。
- CSS 选择器改为 `.service-controls-feedback > span:not(.md-icon)`。

## 三、提交模型不统一（最核心的交互问题）

同一应用内同时存在 9 种生效方式：

| 位置 | 生效方式 |
| --- | --- |
| 外观 | 立即生效 |
| 顶栏服务开关 | 确认后立即生效 |
| 顶栏运行模式 | 确认 → 保存 → 可能还需重启 |
| 设置 › 网络 / 后台 | 草稿 → 逐项保存 → 网络项弹确认 → 顶部"重启并应用" → 再弹确认 |
| 配置试用 | 独立卡片，确认或回退 |
| 路由 › 接收节点路由 | 立即生效 |
| 路由 › 网段 / 范围 | 草稿 → 底栏"保存并应用规则" → 确认 |
| 出口节点 | 选择单选项 → "应用所选出口" → 确认 |
| 情景规则 | 保存后需重启 |

### 具体问题

- **开关被当作草稿使用**。拨动 IPv6 开关并不生效，只在下方出现"有未保存的修改 / 保存 / 重新读取"。这违反了 Android / Material 中开关"拨动即生效"的约定。位置：`webui/src/pages/Settings.tsx:106-109`、`webui/src/pages/Settings.tsx:215-224`、`webui/src/pages/Settings.tsx:247-252`。
- **"放弃修改"按钮文案为"重新读取"**（`tools_retry`），弹出的确认文字是"有未保存的修改"，不是一个问句。
- **警告出现在错误的一步**。保存时弹出"此操作会更改网络配置，连接可能中断"，但保存本身不会断网，重启才会。修改 3 个网络项需要 3 次保存、3 个弹窗，再加 1 次重启和 1 个弹窗。位置：`webui/src/pages/Settings.tsx:122-129`、`webui/src/pages/Settings.tsx:138-140`。
- **更安全的"试用 + 自动回退"藏在页面中段**，常规的"重启并应用"没有回退保护；且试用状态未加载完成前 `trialActive` 默认为真，"重启并应用"会被禁用。试用下拉框显示原始值 `bridge / tun / proxy`，状态行显示 `tun / local / all`，与顶栏"原生 TUN"的命名不一致。位置：`webui/src/pages/Settings.tsx:39`、`webui/src/pages/SettingsTrial.tsx:111-115`、`webui/src/pages/SettingsTrial.tsx:126-127`。

### 方案：用"变更集 + 安全应用"统一

1. 设置、路由、运行模式中需要重启的修改全部进入同一个待应用变更集。全局吸底栏显示："**3 项更改待应用** · 查看 | 放弃 | 应用"。
2. 点"应用"弹出审阅面板：逐项列出 修改前 → 修改后，并标注"需重启 / 立即生效"。"安全应用"默认勾选，复用现有 trial 后端。重启后弹出倒计时："连接正常吗？[保留] [回退 52s]"，做法类似系统修改分辨率后的确认。后端 `settings-set` 仍是单键写入，面板中逐项展示写入结果。
3. 整个流程只确认一次，放在真正会断网的那一步，按钮文案写成"重启并应用"。
4. 开关只用于立即生效的设置；需要暂存的项放进表单，并配合吸底栏。
5. **出口节点改为一点即切换**：点哪一行就在那一行显示进度，完成后提示并提供 5 秒"撤销"；去掉单独的"应用所选出口"按钮（`webui/src/pages/ExitNodes.tsx:370-378`）。离线节点在行内写明不可用原因。

## 四、状态反馈：重复表述，关键处却缺少操作

| 场景 | 问题 | 位置 |
| --- | --- | --- |
| 已停止 | 健康卡写着"启动服务，让本机重新接入你的私有网络"，但没有启动按钮（首页传入 `showStopped={false}`），只能去找顶栏小开关。"2/3 在线、运行 2d 3h、本机 IP、MagicDNS 已启用"等旧数据仍按实时数据显示 | `webui/src/pages/Dashboard.tsx:174-207` |
| 需登录 | 健康卡与 LoginHero 叠在一起，标题都是"登录到 Tailscale" | `webui/src/pages/Dashboard.tsx:141-176` |
| 读取失败 | 徽章"数据可能过期"、顶栏"状态尚未确认"、卡片"连接状态待确认"说的是同一件事，另有两个重试按钮，且不显示真实错误原因 | `webui/src/components/AppShell.tsx:25-29`、`webui/src/pages/Dashboard.tsx:121-137` |
| 无 root / 桥断开 | 横幅直接显示后端原始字符串，只有一个刷新图标，没有下一步指引（如去授权 root） | `webui/src/components/AppShell.tsx:144-150` |
| 结果未确认 | 三个纯图标按钮 ↻ ✕ ✓，其中"✓"就是关键的解锁操作"确认并关闭"；顶栏只显示"正在处理…"，不说明在处理什么 | `webui/src/components/AppShell.tsx:147-158` |
| 错误提示 | 所有 toast 3.2 秒后自动消失，包括带英文后端原文的错误，来不及读也无法复制 | `webui/src/components/Toast.tsx:16-25` |
| 确认弹窗 | 停止、删除、清空都用通用标题"请确认"和橙色"确认"按钮，没有危险样式，也没有动词 | `webui/src/components/ConfirmDialog.tsx:27-35` |
| 密钥到期 | 契约审查中的 P2 仍未修复：`0001-01-01T00:00:00Z` 会原样显示为"即将到期" | `webui/src/pages/Dashboard.tsx:24-29` |

### 方案

首页连接卡作为唯一状态来源，按状态机决定标题与操作；顶栏胶囊只做镜像，其他位置不再重复表述。

| 状态 | 标题 | 主操作 | 次操作 | 其余卡片 |
| --- | --- | --- | --- | --- |
| 已连接 | 已连接 · 出口 X | 断开 | 重启 | 正常显示 |
| 已停止 | 未连接 | **启动** | — | 灰化，标注"上次数据" |
| 需登录 | 需要登录 | 获取登录链接 | Auth Key | 隐藏 |
| 启动中 | 正在连接… | — | — | 骨架 |
| 读取失败 | 无法读取状态 | 重试 | 查看错误详情 | 灰化，加"最后更新 10:02" |
| 无 root | 需要 root 授权 | 授权说明 | 重试 | 隐藏 |
| 结果未确认 | 上次操作结果未知 | 重新检查 | **我已确认，解除锁定**（文字按钮） | — |

配套改动：

- 错误 toast 常驻到用户关闭，提供"详情 / 复制"；后端错误先映射为本地化文案，原文放在详情中。
- `confirmDialog({ title, body, confirmLabel, tone: 'danger' })`：危险操作使用红色按钮，按钮写动词（如"停止服务""删除 3 个文件"）。
- 禁用按钮改为中性灰，并在按钮下写一行原因，例如"选择一个在线节点后可应用"。

## 五、可发现性与操作密度

### 文件

每个文件一行有 6 个纯图标按钮加 1 个复选框，且图标语义冲突（`webui/src/pages/Files.tsx:148-176`）：

- `open_in_new` 表示"导出到下载目录"，但通常意味着"在新窗口打开"。
- `download` 同时表示"另存为"和卡片底部的"接收"。
- "清空收件箱"的垃圾桶图标紧挨排序按钮。
- 另有孤立的全选图标与接收图标。
- 两种选文件方式：一个带文字（"选择共享存储文件"），另一个只是"+"（`webui/src/pages/FilesSend.tsx:201-204`）。
- 两张指标卡（收件箱 2 / 收件大小 15.2 MiB）占据首屏大块空间（`webui/src/pages/Files.tsx:135-138`）。

方案：点一行即打开文件，行尾放"⋮"菜单（打开 / 分享 / 另存为 / 导出到下载 / 复制路径 / 删除）；长按或勾选进入多选，顶部出现上下文操作栏；"清空收件箱"收进卡片溢出菜单并使用危险确认；指标卡并入标题副文本"2 个文件 · 15.2 MiB"。发送流程改为三步：选设备（在线设备做成选项块）→ 添加文件（一个按钮，展开"系统选择器 / 共享存储"）→ 发送。

### 节点

- 详情弹窗只能看、不能操作：缺少"设为出口""发送文件""复制 MagicDNS 名称"。
- "出口节点：已启用"有歧义，实际含义是"可作为出口节点"（`webui/src/pages/Peers.tsx:340-343`）。
- 设备为 0 时仍显示搜索、筛选、视图切换与"0 个结果"；空状态"没有发现其他节点"缺少引导。

### 隧道

- 最显眼的主按钮是低频的 DERP 测速（`webui/src/pages/Tunnel.tsx:118-124`）。
- MagicDNS 卡默认显示"尚未检查 DNS"，需要手动触发（`webui/src/pages/Tunnel.tsx:182-183`）。
- proxy 模式下最关键的 SOCKS5 地址要跑完自检才出现（`webui/src/pages/Tunnel.tsx:255-257`），应常驻并可复制。
- 网关 IP 被折成"100.69.1 / 38.97"两行，原因是 `.metric-value` 设置了 `overflow-wrap: anywhere` 且字号 25–34px（`webui/src/style.css:135`）。

### 日志

控件卡（页签、搜索、行数、4 个开关、徽章、2 个按钮、提示）比日志视图还大，日志没有级别着色（`webui/src/pages/Logs.tsx:116-150`）。方案：一行"搜索 + 错误 / 警告 / 全部 + ⋮（行数、换行、区分大小写、复制）"；实时刷新改为日志视图标题上的播放 / 暂停图标；视图填满剩余高度；`[Warning]` / `[Error]` 着色。

### 账号

- 已登录时最醒目的主按钮仍是"登录"（`webui/src/pages/Account.tsx:195-233`）。
- 当前账号行显示一个禁用的"切换"；设置了标签的账号不显示邮箱（`webui/src/pages/Account.tsx:176-189`）。

方案：顶部是当前账号卡（标签、邮箱、tailnet）；其他账号列表带"切换"；"添加账户"为次要按钮；"退出登录"使用危险样式。

### 诊断

- 卡片标题固定为"诊断包已生成"，正文却是"还没有诊断包"（`webui/src/pages/Diag.tsx:115-119`），标题应随状态变化。
- 同一页面有两个实心主按钮（"检查本机状态""生成诊断包"）。

## 六、视觉与排版

- **字号偏小**：样式表中 10–11px 出现 49 次，9px 出现 1 次（模式下拉框标签，`webui/src/style.css:62`），正文多为 12–13px。建议次要文字不小于 12px，正文 14px。
- **指标卡对齐不一致**：首页与流量页把图标放在标签前，配合 `justify-content: space-between` 后标签被推到右侧；`MetricCard` 组件则是标签在左、图标在右（`webui/src/components/Basics.tsx:33`、`webui/src/pages/Dashboard.tsx:179-183`）。
- **禁用态像可用态**：`.btn:disabled { opacity: .5 }` 作用在品牌色上，看起来像浅橙色可用按钮（`webui/src/style.css:188`）。
- **两种橙色并存**：`--ft-accent #e76b3c` 与 primary `#b84521`。
- **空间利用**：健康卡约 110px 高只放一行字；每页 26–32px 的 H1 在手机上重复底栏标签；桌面设置行宽约 1000px，标签与控件相距过远，表单宽度应限制在约 720px。
- **截断**：360px 英文界面下运行模式标签被截断。
